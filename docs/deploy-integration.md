# Isolated Yurucommu integration peer

The product-owned entrypoint is `bun run deploy -- yurucommu-integration --environment=integration --phase=<phase>`. It is only for `https://ga-commu-20261012.yurucommu.com` and resources named `yurucommu-ga-20261012-0938-*` in the selected existing Cloudflare account. The published Worker input is the checked-in `v2.4.1` GitHub Release and its `release.lock.json` SHA-256. This does not change or repair the production `yurucommu` Worker, its credentials, data, or schema.

Phases are `preflight`, `resources`, `fresh-schema`, `activate`, and `domain`. Each invocation acts on one phase. `preflight` reads the exact zone/account and full D1, R2, KV, Queue, Worker, and filtered/paginated custom-domain inventories and refuses a name collision or denied/incomplete read. `resources` repeats that check, copies the root OpenTofu model into the private operator directory, and accepts only creation of a fresh D1 database, R2 bucket, KV namespace, two Queues, and the root module's random identifier. The Worker remains disabled. The private state and plan remain in the 0700 operator directory, with state/plan mode 0600 or stricter. Raw tool/API failure diagnostics are written only to unique 0600 files beneath its 0700 `diagnostics` directory; public output prints their paths, never their credential-bearing contents. Existing resources are never imported, deleted, or adopted. A failed or uncertain apply requires authoritative state/provider inspection before any new action.

The `fresh-schema` phase reads the private state's exact D1 id and delegates to the isolated published-Core executor in `scripts/deploy-integration-schema.mjs`. Its mutation boundary is a rollback-qualified D1 whole-script REST query, exact Core 4.1.14 SQL and 35-file SHA map, one immutable migration+ledger script per file, with an exact ascending ledger-prefix readback after each file, no blind retry, and read-only reconciliation after an uncertain response. `activate` checks the exact 35 published migration filenames in the isolated D1 ledger before any Worker plan. It then requires an explicit test-owner password hash, distinct 64-hex encryption key and session salt, all supplied as ephemeral environment variables, and accepts only creation of the Worker, queue consumers, and hourly cron. The root module's OIDC defaults remain empty and unpinned owner claims remain disabled. No secrets belong in the target file; OpenTofu state remains sensitive private operator material.

The `domain` phase requires the exact activated state and no pre-existing custom domain for either the hostname or target Worker across complete filtered inventories. It asks the Worker Custom Domain changeset for exactly one addition and no update, deletion, or DNS conflict, repeats the custom-domain inventory, then writes with `override_existing_origin:false` and `override_existing_dns_record:false`. It reads back the exact hostname, service, and zone. A Worker Custom Domain adds DNS and TLS automatically; the account's current credential cannot read zone DNS, so a public DNS lookup is insufficient to prove absence of an existing record. The changeset and no-override provider flags are the mutation boundary. A failed or indeterminate write needs authoritative readback before any retry. Ordinary noninteractive Wrangler custom-domain publication is unsuitable because it can force override flags. Do not attach a route or take over a wildcard.

Set `YURUCOMMU_INTEGRATION_TARGET` to an absolute link-free 0600 JSON file under a 0700 directory outside all Git worktrees. Its exact keys are `accountId`, `zoneId`, `origin`, `prefix`, `releaseTag`, `artifactSha256` (64 lowercase hex), `sourceCommit` (clean 40-hex HEAD), and `stateDir` (an existing 0700 directory beneath the target's private parent). The exact origin, prefix, tag, and artifact digest are checked against source. The operator supplies only an existing OAuth credential as an ephemeral child-process `CLOUDFLARE_API_TOKEN`; activation additionally requires `TF_VAR_encryption_key`, `TF_VAR_session_hash_salt`, and `TF_VAR_auth_password_hash` from ephemeral process environment. Do not put credentials in command arguments, the target file, or source. OpenTofu state and plan inevitably retain sensitive values and therefore stay in the private operator directory; raw diagnostic files may also contain sensitive provider output. `APPLIED` for resources/activation means only exact create-only OpenTofu plan and private state-address readback. Before claiming a live integration peer, the operator must independently read back the authoritative Worker code artifact/digest and bindings, both Queue consumers and cron, the custom domain, and actual user/auth/storage/federation/browser behavior. The operator must review authority and irreversible effects before each mutation. Later routine code updates require a separate predecessor-preserving integration code surface; the current production `yurucommu-worker` surface remains production-only.

The portable bundle's deliberate D1-safe 0003 override is validated through the owning bundle generator; this fresh native D1 lane executes the exact published Core SQL files, and validates all immutable inputs before its first probe write.

The fresh-schema executor does not split SQL or modify Core trigger bodies. It sends the pinned Core runner’s complete script in one REST `{sql}` request per migration. The identical whole-script mode must first demonstrate duplicate-key rollback on the exact fresh D1. Portable SQLite tests execute all 35 SQL files and nested triggers, but do not qualify REST atomicity or a populated database update.

Activation rechecks the complete Worker inventory before planning and immediately before apply. The Cloudflare Worker upload is a PUT, so these reads cannot atomically exclude a concurrent creator with the exact same reserved fixture name; a create-only private plan is not remote conditional-create proof. A collision is refused and any uncertain upload is reconciled without replay.
