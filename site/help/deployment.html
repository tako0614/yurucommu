デプロイ

Cloudflareへの直接デプロイと、Takosumiによる管理付きインストールの2つから選べます。

Cloudflareへ直接デプロイ

一番短い方法はCloudflareのdeploy画面を使うことです。D1、KV、R2、Queuesが 作成され、Workerにbindingされます。

Deploy to Cloudflareを開く

CLIからデプロイ

git clone https://github.com/tako0614/yurucommu.git
cd yurucommu
bun install
bunx wrangler login
bunx wrangler d1 create yurucommu-db
bunx wrangler queues create yurucommu-delivery
bunx wrangler queues create yurucommu-delivery-dlq
bunx wrangler secret put ENCRYPTION_KEY
bunx wrangler secret put AUTH_PASSWORD_HASH
bun run deploy

wrangler.jsoncが直接経路の正本です。KVとR2はWranglerが初回deploy時に provisionします。bun run deployはfullstack Workerをビルドし、 @takosjp/yurucommu-coreのD1 migrationを適用してから公開します。

Takosumiでインストール

yurucommu は GitAddress の URL・ref・path で指定できる plain OpenTofu module です。Takosumi はこれを OpenTofu Capsule（Takosumi が管理する1つのインフラ単位）として扱います。Takosumi では、取得元となる Source（Git URL・ref・パス）を Project （ワークスペース内のグループ）に登録し、cloudflare provider にどのクラウド接続（ProviderConnection）を使うかを ProviderBinding（接続先の割り当て）で指定します。変更内容（Plan） を作成してレビューしたうえで適用（Apply）すると、Worker / storage / routing が作成されます。

Source登録 / Plan / Apply

本番へのデプロイは Takosumi の実行記録（Run）として記録されます。 Source を Project に登録すると、Takosumi が Capsule を Git から読み、検証して Plan を作成します。ProviderConnection を ProviderBinding で指定し、変数・secret を入力したうえで Plan を作成します。レビューした Plan を承認して Apply すると、復元ポイント（StateVersion）・実行結果（Output）・履歴 （AuditEvent）が記録されます。 

GitAddress:
url: https://github.com/tako0614/yurucommu.git
ref: main
path: .
flow: Source 登録 -> Takosumi が Git から読み検証 -> Plan Run -> Apply Run -> StateVersion + Output

2つの正本

Cloudflare直接経路はwrangler.jsonc、Takosumi管理経路は main.tfとoutputs.tfが正本です。どちらも同じ dist/yurucommu-worker.jsとcore migrationを使います。

OpenTofuはTakosumiがPlan、Apply、state、output、auditを管理するために使います。 Cloudflareへ直接デプロイするだけならOpenTofuは必要ありません。

CI/CDパイプライン

CIではbuild / testとTakosumi用artifactを検証します。Cloudflare直接経路は WranglerまたはWorkers Builds、管理付き経路はTakosumiのPlan / Applyを使います。

ロールバック

Cloudflare直接経路ではWorkersのversion / rollbackを使います。Takosumi経路では 過去のStateVersionとpin済みSourceを基にPlan / Applyします。

ログの確認

直接経路はwrangler tailとCloudflare dashboard、Takosumi経路は Runログ、Activity、Apply Runの証跡を確認します。

よくあるエラー

「Script too large」エラー

Workerのサイズ制限（1MB）を超えている場合：

  • 不要な依存関係を削除
  • コードの最適化
  • Workers有料プランにアップグレード（10MB制限）

「D1 database not found」エラー

wrangler.jsoncのDB bindingと、初回に作成した yurucommu-dbを確認してください。

「R2 bucket not found」エラー

バケット名が正しいか、作成済みか確認してください。
