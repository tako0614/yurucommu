デプロイ

Cloudflare 直接経路と、operator が運用する Takosumi の plain OpenTofu 経路があります。Takosumi Cloud の選択式インストールはまだ公開していません。

Cloudflare 直接経路

設定正本は wrangler.jsonc です。D1・KV・R2・Queue と secret を用意し、利用者または operator 自身の runbook、credential、 承認、migration、rollback policy で管理します。この self-host deployment は公式 distribution の公開とは別です。

Deploy to Cloudflareを開く

ローカルで候補を検証

git clone https://github.com/tako0614/yurucommu.git
cd yurucommu
bun install
bun run check
bun run test
bun run build:worker

ここで作る Worker bundle は self-host 用です。repository の task や check は production mutation authority を与えません。

operator 管理の Takosumi

yurucommu は Git URL・ブランチ・パスで指定できる、そのまま実行できる OpenTofu module です。Takosumi はこれを OpenTofu Capsule（Takosumi が管理する 1 つのインフラ単位）として扱います。Takosumi では、取得元となる Source（Git URL・ブランチ・パス）をワークスペース内の Project に登録し、Cloudflare provider が使うクラウドアカウント接続（ProviderConnection）を ProviderBinding（provider への接続の割り当て）で指定します。 変更内容（Plan）を作成してレビューしたうえで適用（Apply）すると、Worker・ストレージ・ルーティングが作成されます。

これは operator-reviewed な plain OpenTofu 経路です。Takosumi Cloud の Store 候補は、portable provider/Form Package、migration activation、rollback の実環境証跡が揃うまで selectable にしません。

Source 登録 / Plan / Apply

本番へのデプロイは Takosumi の履歴（Run）として記録されます。 Source を Project に登録すると、Takosumi が Capsule を Git から 読み込み、検証して Plan を作成します。ProviderConnection を ProviderBinding で指定し、変数・secret を入力したうえで Plan を作成します。レビューした Plan を承認して Apply すると、復元ポイント（StateVersion）・実行結果（Output）・履歴（AuditEvent）が記録されます。 

GitAddress:
url: https://github.com/tako0614/yurucommu.git
ref: main
path: .
flow: Source 登録 -> Takosumi が Git から読み込み・検証 -> Plan -> Apply -> 復元ポイント + 実行結果

2つの管理元

Cloudflare 直接経路は wrangler.jsonc、Takosumi 管理経路は main.tf と outputs.tf が管理元です。どちらも同じ dist/yurucommu-worker.js と core マイグレーションを使います。

OpenTofu は Takosumi が変更内容の確認・適用・状態・実行結果・履歴を管理するために使います。 Cloudflare へ直接デプロイするだけなら OpenTofu は必要ありません。

CI/CDパイプライン

CI ではビルド・テストと Takosumi 用のビルド成果物を検証します。Cloudflare 直接経路は Wrangler または Workers Builds、管理付き経路は Takosumi の Plan / Apply を使います。

ロールバック

Cloudflare 直接経路では Workers の version / rollback を使います。Takosumi 経路では 過去の復元ポイントと固定済みの取得元を基に Plan / Apply します。

ログの確認

直接経路は wrangler tail と Cloudflare dashboard、Takosumi 経路は実行ログと履歴を確認します。

よくあるエラー

「Script too large」エラー

Workerのサイズ制限（1MB）を超えている場合：

  • 不要な依存関係を削除
  • コードの最適化
  • Workers有料プランにアップグレード（10MB制限）

「D1 database not found」エラー

wrangler.jsoncのDB bindingと、初回に作成した yurucommu-dbを確認してください。

「R2 bucket not found」エラー

バケット名が正しいか、作成済みか確認してください。
